# Cryptographic Attacks

This lecture covers the most common cryptographic attacks and the defences against them.

One distinction runs through all of them: a *key* generated by a random number generator is attacked by trying out the whole key space, while a *password* chosen by a human is attacked by trying likely candidates first. The second is far cheaper, which is why passwords need different defences than keys.

## Brute Force Attacks

The brute-force attack describes an attack where the attacker tries to guess the key by trying every possible key-combination.
Assuming a key can only consist out of 4 letters, the attacker will start trying to decrypt the data using the keys 'A', 'B', 'C', 'D'... up to "ZZZZ", until it finds the desired key.
While this attack is suitable for short key lengths, it becomes nearly impossible to guess a key which consists of many different letters.
The attacker needs to attempt A^n combinations to be guaranteed to find the key, where A describes the size of the used alphabet (f.E., for upper & lowercase letters: A-Z (26) + a-z (26) => 52) and n describes the length of the key. On average, half of that is enough.
Note that every added character multiplies the effort by A, so the cost grows exponentially with the key length. A key of sufficient length is therefore out of reach for brute force, while a short one falls within hours.
In order to protect against brute-force attacks, use keys generated at full length by a cryptographic random number generator (for example 128 bit or more for symmetric keys) rather than keys derived from something short and memorable.

## Dictionary Attacks

For dictionary attacks, the attacker does not try every combination but iterates through a pre-existing list of likely candidates.
There are many such wordlists available for download, assembled from past data breaches and therefore containing exactly those passwords people actually choose. Tools additionally apply rules to each entry (appending digits, swapping letters for similar-looking symbols), which covers the usual variations.
This is why a password can be long and still fall quickly: predictability counts for more than length.
In order to avoid your keys being guessed via dictionaries, you are encouraged to use long keys, consisting of different letters, numbers and symbols. Besides that, you should not re-use any of your passwords.

## Rainbow Tables

Rainbow table attacks involve the use of precomputed tables that map input values (not exclusively passwords) to hash values. Instead of repeatedly hashing potential inputs during an attack, the attacker can quickly look up the hash in a precomputed table to find the corresponding original input.
A rainbow table does not store every input/hash pair; it stores only the start and end of long chains of alternating hashing and reduction steps, and recomputes the chain on lookup. That is where the tradeoff between performance and storage comes from:

- Compared to brute-force attacks, they require much less computational power at attack time, because the work was already done during precomputation.
- Compared to a plain lookup table of every input and its hash, they demand far less storage.
- To prevent rainbow table attacks, use a salt: a random value that is generated **per password**, prepended or appended before hashing, and stored next to the hash. It is not a secret, and it is not "changed regularly". Its purpose is that no two users share a precomputation, so any precomputed table is useless and the attacker has to start over for every single hash.
- Salting alone does not make a fast hash safe. Password hashes should be computed with a deliberately slow key derivation function such as Argon2, scrypt or bcrypt (Argon2 and scrypt are additionally memory-hard), which raises the cost of every single guess. SHA-256, even salted, can be computed billions of times per second on a GPU.

## Side-Channel Attacks

Side-channel attacks focus on exploiting information leaked during the execution of cryptographic algorithms. This could include timing information, power consumption, or electromagnetic radiation.
By analyzing these side-channel leaks, an attacker may gain insights into the cryptographic keys being used.
To defend against side-channel attacks, implementations need explicit countermeasures, such as constant-time algorithms that do not reveal information through timing variations.
